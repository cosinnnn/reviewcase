# 第一轮（新增 41 条）复核意见

复核对象：`gz_xpeng_nav_supplement_result.csv`（全量 82 次）+ `trial_first3_result.csv`（试跑 6 次）+ Fuyao 生成的第一版汇总报告。
总汇总时请按本文件修正第一轮判定，再计算通过率。

## 1. 判定标签说明

第一版只有"符合 / 不符合 / 待复核"三档，过于二元。总汇总改用四档：

| 标签 | 含义 | 计入通过率 |
|---|---|---|
| 符合 | 结果类型和地点都对 | 分子、分母都算 |
| 合理偏差 | 和预期类型不同，但对用户是合理回答（如给出 2 个真实候选让用户选） | 分子、分母都算，单独列出 |
| 不符合 | 地点错、编造、过时、该澄清没澄清、该兜底却硬导航 | 只算分母 |
| 环境限制 | 失败主要是测试接口没有注入车辆定位造成的（query 没给城市，模型只能猜） | 不计入通过率，单独列出 |
| 待高德复核 | 结论取决于某个店名/地址是否真实 | 暂不计入，复核后再归类 |

## 3. 稳定性证据（同一 query 两次结果不同）

试跑和全量跑了相同的前 3 条，结果出现明显差异：

| id | query | 模型 | 试跑 | 全量 |
|---|---|---|---|---|
| 1 | 导航去正佳广场的海底捞 | flash | 编造"正佳广场内设有海底捞" | 编造"正佳广场内有海底捞门店"（两次都编造） |
| 1 | 同上 | plus | 正确：暂未查询到海底捞 | 正确：暂无海底捞门店（两次都对） |
| 2 | 带我去体育西路的海底捞 | plus | 只给了"天河城店" | 正确给出"体育西路店" |
| 2 | 同上 | flash | 正确给出"体育西店" | 编造"正佳广场店" + "天河城店" |
| 3 | 导航去广州东站附近的海底捞 | plus | 大排档东站店 + 中泰广场店 | 东站店 + 中泰广场店 |

结论：单次跑批的通过率有随机波动，flash 波动更大。重点 query 需要多跑几次（建议 3～5 次）才能下结论。

## 4. 第一轮最值得汇报的发现

1. **过时信息**：两个模型都把"小鹏汽车总部"导到旧址松岗大街8号（新址为丰庄大街10号小鹏科技园，2025-10 启用）。
2. **编造不存在的店**：flash 两次都说正佳广场有海底捞；plus 两次都正确说没有。
3. **已停运/已结束不提示**：广园客运站已停运、乞巧节已结束，两个模型都没有讲清楚。
4. **多候选不澄清**：同品牌多店（炳胜）、多入口（火炉山）时直接挑一个，有时还挑错。
5. **缺定位**：测试接口不注入车辆位置，"附近""没说城市"的 query 失败率高，这部分要和线上环境区分开。
